PHASE 1 — ENGINE INFRASTRUCTURE (GDScript changes)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

These require changes to GameContext.gd, TurnManager.gd, AbilityInterpreter.gd,
RunStateMachine.gd, EncounterProcessor.gd, and/or CorpTurnAI.gd.
New decision-maker methods may be needed in HumanDecisionMaker.gd and SimRunnerAI.gd.
Each item notes the affected files.

─────────────────────────────────────────────────────────────────────────────
1A. CHARGE MECHANIC
─────────────────────────────────────────────────────────────────────────────
Used by: orca, flux_capacitor, (and possibly future cards)

Charge = "Add 1 power counter to a card that already has one."

Changes required:
• AbilityInterpreter: new effect type `charge_card`
  - Collect all installed runner cards (runner_rig) that currently have at
    least 1 power counter.
  - Ask runner_decision_maker.choose_card_to_charge(candidates, ctx) to pick one.
  - Add 1 power counter to the chosen card.
  - If no candidates exist, log "No installed cards with power counters — charge has no effect."
• HumanDecisionMaker: new method `choose_card_to_charge(candidates, ctx) -> InstalledCard`
  - Present the candidate list for player to pick.
• SimRunnerAI: new method `choose_card_to_charge(candidates, ctx) -> InstalledCard`
  - Heuristic: prefer the card with the most power counters; or the one that
    benefits most from additional counters (e.g., WAKE Implant for R&D access).

The `charge_card` effect dict:
  { "type": "charge_card" }
  (no params — always charges exactly 1 card, mandatory if any valid targets)

1B. MARK MECHANIC
─────────────────────────────────────────────────────────────────────────────
Used by: info_bounty, tunnel_vision (icebreaker), tsakhia_bankhar_gantulga

The Runner may identify a mark — a randomly chosen central server — at turn
start. Once identified for the turn, it is locked in. Some cards trigger on
runs against the mark; tunnel_vision also breaks ice protecting the mark.

Changes required:
• GameContext:
  - New field `runner_mark_server: String = ""`   (empty = no mark this turn)
  - New field `runner_ran_on_mark_this_turn: bool = false`
  - New field `runner_breached_mark_this_turn: bool = false`
  - Reset all three at start of each Runner turn.
• TurnManager._runner_turn(): clear mark fields at turn start.
• AbilityInterpreter: new effect type `identify_mark`
  - If runner_mark_server is already set this turn, do nothing.
  - Otherwise, pick a random central ("hq", "rd", "archives") and set
    runner_mark_server.
  - Log: "Runner identifies mark: [server name]."
• New condition type `run_target_is_mark`
  - True when ctx.run_target_server == ctx.runner_mark_server (and mark != "").
• New condition type `runner_breached_mark_this_turn`
  - True when ctx.runner_breached_mark_this_turn.
• RunStateMachine / TurnManager: when a run on the mark server ends
  successfully (i.e., runner breached), set runner_breached_mark_this_turn = true.
• Info Bounty (resource) registers on `run_ends` event; checks conditions.
• Tunnel Vision (icebreaker): uses `run_target_is_mark` condition to gate
  break ability so it only works against ice protecting the mark server.

Effect dict for identify_mark:
  { "type": "identify_mark" }

1C. RUNNER ALLOTTED CLICK BONUS
─────────────────────────────────────────────────────────────────────────────
Used by: basilar_synthgland_2kvj (+1 click per turn)

  where runner_allotted_click_bonus is computed by scanning runner_rig for
  installed Basilar Synthgland (and any future +click hardware).
  Alternatively, compute it inline: scan runner_rig for `card_id == "basilar_synthgland_2kvj"`.
  Each installed copy adds +1. (Only 1 copy allowed in standard; but handle N copies.)
• Copy runner_allotted_click_bonus in GameContext.clone() for simulation.

1D. ADDITIONAL OPERATION COSTS
─────────────────────────────────────────────────────────────────────────────
Used by: end_of_the_line (remove 1 tag), distributed_tracing (spend [click]),
         finality (suffer 1 core damage), hypoxia (tagged-only pre-condition)

The engine already handles operation play-conditions (e.g. pre_play_condition).
We need to extend TurnManager where Corp plays operations to check and pay
additional costs before resolving the effect.

Changes required (TurnManager, Corp operation path):
• Support `additional_cost_remove_tag` key in on_play dict:
  - Before resolving effects: if runner_tags > 0, remove 1 tag. Else, refuse.
• Support `additional_cost_spend_click` key in on_play dict:
  - Before resolving effects: if corp_clicks > 0, spend 1 corp click. Else, refuse.

For Runner events with additional costs (finality — core damage):
• Support `additional_cost_core_damage` key in on_play dict:
  - Before resolving effects: deal 1 core damage to Runner. This is mandatory;
    if it kills the runner, the event still resolves but runner is flatlined.

These additional costs should be checked/paid in TurnManager._do_play_runner_event()
and TurnManager._do_play_corp_operation() before the main ability fires.
The JSON representation can use top-level keys on the ability definition dict
or a dedicated `additional_costs` array.

─────────────────────────────────────────────────────────────────────────────
1E. DEREZ EFFECTS
─────────────────────────────────────────────────────────────────────────────
Used by: bloop (derez another harmonic ice as additional rez cost)

The engine already has `derez_self` for Lycian Multi-Munition and Stegodon.
We need:
• AbilityInterpreter: new effect type `derez_ice_by_subtype`
  - params: { "subtype": "harmonic", "exclude_self": true, "chooser": "corp" }
  - Corp chooses any rezzed ice with the given subtype (excluding self if flag set).
  - That ice is derezzed.
• For Bloop specifically: this functions as an ADDITIONAL REZ COST, not a
  post-rez effect. The rez validation logic in TurnManager must check that the
  Corp can pay this cost (has another rezzed harmonic ice) before allowing the
  rez. If valid, prompt Corp to choose which harmonic ice to derez, derez it,
  then proceed with Bloop's rez.
  Implementation: add a special `additional_rez_cost` key to Bloop's ability
  definition, handled in the ice rez flow.

A general `derez_installed_card` effect type (Corp chooses any rezzed card)
would also be useful for future expansions.

1F. SUPERDEEP BOREHOLE WIN CONDITION
─────────────────────────────────────────────────────────────────────────────
Used by: superdeep_borehole

This is a unique win condition: asset loads 6 "bad_publicity" counters on rez;
each Corp turn start, remove 1 from the asset (not from the Corp's bad publicity
pool — this is a new isolated counter on the card itself); when zero remain,
Corp wins immediately.

Changes required:
• This can be handled entirely in JSON via existing counter mechanics, EXCEPT
  for the "win the game" trigger.
• AbilityInterpreter: new effect type `win_game`
  - params: { "winner": "corp" }
  - Sets ctx.game_over = true, ctx.winner = "corp".
• Borehole's on_rez loads `counter: "bad_publicity"` (6 counters on the card).
• Borehole's corp_turn_begin trigger removes 1 "bad_publicity" counter from self,
  then checks if counter == 0: if so, fires `win_game`.
• The `self_trash_if_empty` effect already handles trashing when empty; we need
  a `win_game_if_self_counter_empty` effect or similar conditional.
  Simplest: after removing counter, check `if self.get_counter("bad_publicity") == 0: win`.

1G. NIGHTMARE ARCHIVE: NEGATIVE AGENDA POINT
─────────────────────────────────────────────────────────────────────────────
Used by: nightmare_archive

On access, Runner may choose to add this to their score area as an agenda
worth −1 agenda point. If they decline: 1 core damage + RFG.

Changes required:
• The score area and agenda point system currently only handles positive points.
  We need to allow −1 point agendas in runner_score_area.
• GameContext: runner_score should support subtraction from negative-point agendas.
  The runner_score is likely summed from cards in runner_score_area. Check that
  negative point values are handled correctly in scoring and win-condition checks.
• AbilityInterpreter: new effect type `nightmare_archive_on_access`
  - Offer Runner the choice: add to score area (−1 point) or decline.
  - If added: move asset to runner_score_area (with agenda_points = −1).
    Note: this means the Runner's score may go below their previous total.
  - If declined: deal 1 core damage, then RFG self.
• Also: "While accessed in R&D, must be revealed" — this is a passive reveal
  flag. Add `reveal_when_accessed_in_rd: true` to the ability definition.
  In the R&D breach loop, check for this flag and reveal the card before
  deciding whether Runner accesses it.
• HumanDecisionMaker: `choose_nightmare_archive(ctx) -> bool`
  (true = add to score area as −1, false = decline and take damage)

1H. ISSUAQ IDENTITY: REDUCED WIN CONDITION
─────────────────────────────────────────────────────────────────────────────
Used by: issuaq_adaptics_sustaining_diversity

Whenever Corp scores an agenda not installed or advanced this turn: place 1
power counter on this identity. For each counter, need 1 fewer agenda point to win.

Changes required:
• GameContext: method `corp_points_to_win()` must account for Issuaq counters.
  Currently corp needs 7 agenda points to win. With Issuaq counters, they need
  7 − N points. Add a query:
    func corp_points_to_win() -> int:
      var base := 7
      if corp_identity != null and corp_identity.id == "issuaq_adaptics_sustaining_diversity":
        base -= corp_identity_counters.get("power", 0)
      return max(1, base)  # can't go below 1 point needed
• Check win condition: wherever we check `corp_score >= 7`, replace with
  `corp_score >= corp_points_to_win()`.
• TurnManager: when Corp scores an agenda, fire `corp_scores_agenda` event
  with flag `was_installed_or_advanced_this_turn`. Issuaq listens for cases
  where this flag is false (the agenda was not installed or advanced this turn).
  This needs tracking in GameContext:
  - `corp_advanced_or_installed_agenda_this_turn: bool` (reset each turn)
  - Set to true when Corp installs a card or advances a card during their turn.

Special notes on HUSH:
  Hush: "Install only on ice. Host ice cannot gain abilities and loses all
  abilities except its printed subroutines. [click]: move to another ice."
  — The "cannot gain abilities and loses all non-subroutine abilities" effect
    means on-rez triggers, passive modifiers, etc. on the host ice are all
    suppressed. This requires a `hush_applied` flag on InstalledCard that
    suppresses all non-subroutine ability lookups in AbilityRegistry/AbilityInterpreter.
    Also suppresses approach_server, on_rez, etc. triggers.
  — The [click] move ability means Hush itself can be relocated.
  — Implementation: add `is_ability_suppressed: bool` to InstalledCard, set
    it when Hush is hosted, clear it when Hush moves or is trashed.

Special notes on TREMOLO:
  "3cr − 1cr per installed cybernetic hardware" break cost.
  — Need GameContext query: count_installed_cybernetic_hardware() → int
    (runner_rig cards with subtype "cybernetic" that are hardware).
  — At time of break, cost = max(0, 3 − count_cybernetic). Apply dynamically.

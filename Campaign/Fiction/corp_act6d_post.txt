THE LEARNING CURVE: CONCLUDED
by Desh Fuentes-Calloway

The supervisor's warning about unpredictability proved accurate to a point. Dewi ran a server on the first turn that no experienced runner would have run — the innermost server, fully protected, with an ICE configuration that the Syndicate had stacked specifically because a learner might not register the risk indicators. The run failed. The ICE held. Dewi paid the tax.

The second run was better. More considered. The resource engine had started to stabilize by then, Groovy's accumulation patterns finding their rhythm. The Syndicate's monitoring team noted a visible improvement in run decision quality between the first engagement and the fourth. Dewi was learning in real time.

The Syndicate was faster.

Three agendas advanced while Dewi's resource base was still assembling. The credit reserves built behind the agenda score, and when Groovy finally began to produce enough pressure to threaten server two, server two was triple-layered and the outer servers had been restructured to force a longer approach.

Final score: Syndicate seven, runner three. Dewi found the three points through a run that was genuinely clever — the kind of move that appears in the after-action report with a notation: *watch for this player.*

The Syndicate is watching.

The learner learned. Not fast enough, not this time.
